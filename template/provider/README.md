# Hostenv provider template

This template boots a provider flake that consumes hostenv projects and generates the provider deployment plan.

## Quick start

1. Initialize the provider flake:

   ```bash
   nix flake init -t gitlab:woolwichweb/hostenv#provider
   ```

2. Edit `flake.nix`:
   - Add each client project as an `organisation__project` input.
   - Set `provider.nodeFor` / `provider.nodeSystems` for your nodes.
   - Set `provider.hostenvHostname` in `flake.nix`.

3. Enter the development shell:

   ```bash
   direnv allow  # or: nix develop
   ```

4. Generate the deployment plan:

   ```bash
   nix run .#hostenv-provider -- plan
   ```

The generated `plan.json`, `state.json`, and `flake.nix` under `generated/` are the provider-side deployment artifacts. `plan.json` is always regenerated by evaluating the configured project inputs; `state.json` is reused when present to retain persistent provider state such as environment UIDs.

## Admin UI template

When the provider UI is enabled, it regenerates `flake.nix` from `flake.template.nix` while preserving the generated project-input block.

Edit `flake.template.nix` to make structural changes while keeping the marker used by the UI.

## Customisation tips

- Ensure client project inputs point at the `.hostenv` flake (e.g. `dir=.hostenv`) and export `outputs.lib.hostenv`.
- Add extra Haskell deps for the dev shell via `provider.haskellDevPackages` (appended to `hostenv.haskell.devPackages`).
- Add provider-specific modules under `modules/` in your repo (e.g. `modules/nixos/<aspect>.nix`) and import them alongside `hostenv.flakeModules.provider` using your preferred module loader.
